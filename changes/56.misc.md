The RFC 4648 codecs, the 85 pair and every `radixly.compat.base64` function run on one engine per codec: encoders write two characters per table lookup, decoders judge whole groups at once, and the drop-in resumes those kernels between the characters it still reads one by one. Against the standard library on 3.15 the encoders run 1.5 to 2.2 times as fast, the 85 and base16 decoders 2.6 to 4 times, `urlsafe_b64decode` 1.9 times; base64 and base32 decoding of large input stays at parity with the same scalar kernels and leads at small and medium sizes. On 3.14 and earlier `b64decode` runs 3.5 times as fast as before.
