# z85

```python
from radixly import z85

z85.encode(b"hi")          # 'xLv'
z85.decode("xLv")          # b'hi'
z85.encode(b"\xff" * 4)    # '%nSc0'
```

## Alphabet

`0` to `9`, `a` to `z`, `A` to `Z` and `.-:+=^!/*?&<>()[]{}@%$#`. No quotes, no backslash, so it sits in a JSON string or a quoted literal unescaped; no backquote, `;`, `|`, `_` or `~`, so it crosses a pipe-split column or a backquoted span. ZeroMQ defines Z85 for payloads of whole words; this codec takes any length with the standard library's tail rule.

::::{grid} 1 2 2 2
:gutter: 2

:::{grid-item-card} Use it for
CurveZMQ keys, and channels that treat backquote, `|`, `;`, `_` or `~` specially.
:::

:::{grid-item-card} Reach for another codec when
the text goes into a URL, where `%`, `#`, `^`, `<>`, `[]`, `{}`, `/`, `?`, `&`, `=` and `+` all carry meaning ({doc}`base64url`), or into a shell unquoted (single quotes are safe).
:::

## Truncation

As base85: a cut inside a group of five raises {class}`~radixly.DecodeError` unless the tail happens to spell a shorter payload exactly; a cut on a group boundary decodes to a prefix. About three cuts in ten pass.

## Standard library

`radixly.compat.base64.z85encode` and `z85decode` run on this codec's C with the standard library's behavior, on the interpreters that have them (3.13 and later). See {doc}`../compat`.
