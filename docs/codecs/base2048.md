# base2048

11 bits per character from 2,048 code points below U+1100, decoded strictly
and canonically.

[qntm's base2048](https://github.com/qntm/base2048) was built for Twitter,
which counts every code point from U+1100 upward as two. It stays below that
line with an alphabet of letters and numerals from two dozen scripts. A
leftover of 1 to 3 bits at the end goes into a short character from a second
alphabet of 8, a leftover of 4 to 10 into a padded 11-bit character: `n` bytes
become `ceil(8 * n / 11)` characters. radixly's encoder matches the reference
implementation byte for byte on qntm's published test vectors. The decoder is
stricter than qntm's: a final character that carries no payload bits is
rejected, so one payload has exactly one accepted spelling.

## When to use it

100 code points hold 137 bytes, where base64 holds 75. Its niche is a channel
that counts characters but frowns on the high end of the BMP or on the
supplementary planes: base2048 never leaves the first 4,352 code points, and
its output reads as letters rather than a wall of ideographs. The alphabet
has no whitespace, control, punctuation, symbol or combining characters and
is stable under every normalization form. Because it dips into ASCII, a short
payload can encode to a plain string: `b"\x00"` is `"F"`.

It does not save bytes: as UTF-8 most characters cost two or three. If the
channel accepts all of the BMP, {doc}`base32768` carries more.

## Truncation behavior

base2048 carries no length and no checksum. The decoder only checks that the
last character ends in padding bits that are all ones, so a string cut after
`k` characters passes whenever its `11 * k mod 8` leftover bits happen to
look like padding: always when that remainder is 0, otherwise with
probability one in 2^remainder on random data. Measured over random payloads
and every cut position, about 23% of truncated strings decode without an
error, every one of them to a prefix; the rest raise
{class}`~radixly.DecodeError` at the last character.

```python
from radixly import base2048

payload = bytes(range(20))
text = base2048.encode(payload)            # 15 characters
base2048.decode(text[:8]) == payload[:11]  # True: 88 bits, no padding to check
```

If you need to know whether a string arrived whole, carry a length or
checksum alongside it, or use {doc}`uro14`, whose length prefix rejects every
truncation below its 16,384-byte window.
