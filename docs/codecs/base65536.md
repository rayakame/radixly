# base65536

16 bits per character: every pair of bytes becomes one code point.

[qntm's base65536](https://github.com/qntm/base65536) uses 256 blocks of 256
consecutive code points. The second byte of a pair picks the block, the first
the offset inside it, and a final odd byte gets a character from a block of
its own, so nothing needs padding: `n` bytes become `ceil(n / 2)` characters.
Most blocks lie outside the Basic Multilingual Plane, so most characters are
surrogate pairs in UTF-16. radixly's encoder matches the reference
implementation byte for byte on qntm's published test vectors.

## When to use it

100 code points hold 200 bytes, the most of any codec here. Pick it when the
channel counts code points and accepts the supplementary planes. Every
character is assigned, non-combining and stable under all four Unicode
normalization forms, with no whitespace or control characters among them.

It loses where a channel counts UTF-16 code units: an astral character is
two units, so its 16 bits per code point become 8 per unit. A channel that
strips astral characters destroys the text outright. In both cases
{doc}`base32768` is the safer choice. It does not save bytes either: as UTF-8
most characters cost four.

## Truncation behavior

Every prefix of a base65536 string is itself valid. Cut one after `k`
characters and it decodes, without an error, to the first `2 * k` bytes of
the payload. There is no padding, no length and no checksum, so the decoder
has nothing to object to.

```python
from radixly import base65536

payload = bytes(range(20))
text = base65536.encode(payload)            # 10 characters
base65536.decode(text[:8]) == payload[:16]  # True, always
```

If a shortened string must be caught, carry a length or checksum alongside
it, or use {doc}`uro14`, whose length prefix rejects every truncation below
its 16,384-byte window.
